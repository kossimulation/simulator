# Архітектура

```
┌────────────────────────────────────────────────────────────┐
│ C# (.NET 8)  managed/                                      │
│  Simulator.Cli ──► Simulator.Core (Simulation, P/Invoke)   │
└──────────────────────────┬─────────────────────────────────┘
                           │  C ABI: native/include/simcore/simcore.h
┌──────────────────────────▼─────────────────────────────────┐
│ C++17 ядро  native/  (libsimcore.so / simcore.dll)         │
│  Simulation: RK4, сила тяжіння, контакт із землею, трим    │
│  VehicleModel ◄── FixedWing, Helicopter (ручний C++)       │
│              ◄── адаптери до коду з Simulink (generated/)  │
└──────────────────────────▲─────────────────────────────────┘
                           │  Embedded Coder (C++ class) + packNGo
┌──────────────────────────┴─────────────────────────────────┐
│ MATLAB / Simulink  matlab/                                 │
│  params/*.m, models/*.slx, codegen/generate_code.m         │
└────────────────────────────────────────────────────────────┘
```

## Шари та відповідальність

**C++ ядро (`native/`)** відповідає за всю фізику та числове інтегрування.
Воно не залежить ні від .NET, ні від MATLAB.

- `rigid_body.*`: рівняння Ньютона-Ейлера для 6 ступенів свободи
  (кватерніон орієнтації, головні моменти інерції).
- `atmosphere.*`: стандартна атмосфера ISA до 20 км.
- `vehicle.hpp`: інтерфейс `VehicleModel`. Модель повертає лише
  аеродинамічні та тягові сили й моменти в зв'язаних осях.
- `fixed_wing.*`: легкий літак, лінійні аеродинамічні похідні.
- `helicopter.*`: легкий вертоліт, несучий гвинт за імпульсною теорією,
  нахил площини обертання від циклічного кроку, жорсткий втулковий момент,
  хвостовий гвинт.
- `simulation.*`: RK4 з підкроками ≤ 5 мс, сила тяжіння, спрощений контакт
  із землею, трим (метод Ньютона: 6 невідомих, 6 прискорень).
- `c_api.cpp`: плоский C ABI, єдина межа, яку бачить C#.

**C# (`managed/`)** відповідає за оркестрацію, сценарії, запис телеметрії і
в майбутньому за UI та візуалізацію.

- `Simulator.Core`: `Simulation` (IDisposable, `SafeHandle`) поверх
  `[LibraryImport]`. Кожна структура дзеркально повторює `simcore.h`, а тест
  `NativeStructLayoutsMatchHeader` разом із `static_assert` у `c_api.cpp`
  стежать, щоб розкладка в пам'яті не розійшлася.
- `Simulator.Cli`: трим → ступінчастий вхід → CSV.

**MATLAB/Simulink (`matlab/`)** призначений для розробки та валідації
підсистем (аеродинаміка, гвинт, двигун, САК) з подальшою генерацією C++.

## Системи координат і знаки

- Світова система NED: x на північ, y на схід, z вниз. Висота дорівнює `-pos_down`.
- Зв'язана система FRD: x вперед, y праворуч, z вниз.
- Органи керування нормовані: `throttle` ∈ [0, 1] (газ або загальний крок),
  `pitch`/`roll`/`yaw` ∈ [-1, 1]. Додатне значення означає ніс угору, крен
  праворуч, ніс праворуч.

## Підключення моделі з Simulink

1. Модель має реалізувати контракт портів із `matlab/models/README.md`.
2. `generate_code('model')` створює `native/generated/model/`.
3. Напишіть адаптер, що реалізує `VehicleModel`, наприклад
   `native/src/simulink_<model>.cpp`:

```cpp
#include "model.h"          // згенерований клас
#include "vehicle.hpp"

class SimulinkHeli final : public simcore::VehicleModel {
public:
    SimulinkHeli() { model_.initialize(); }
    ~SimulinkHeli() override { model_.terminate(); }
    // ... name(), mass_properties(), compute_wrench():
    //   заповнити входи з RigidBodyState/Controls/Environment,
    //   викликати model_.step(), зібрати Wrench з виходів.
private:
    mutable model model_;   // назва класу та доступ до I/O залежать від
                            // налаштувань Embedded Coder і версії MATLAB
};
```

4. Додайте тип апарата в `sim_vehicle_type`, `sim_create` і `VehicleType` (C#).
5. Зберіть ядро з `-DSIMCORE_WITH_GENERATED=ON`.

> **Важливо про стан моделі.** RK4 викликає `compute_wrench` 4 рази за
> підкрок. Якщо модель Simulink має дискретні стани (фільтри, інтегратори,
> САК), `step()` треба викликати **рівно один раз за підкрок**, а між
> викликами тримати виходи незмінними (zero-order hold). Інакше стан моделі
> просуватиметься вчетверо швидше. Модель без станів (чисто алгебраїчна
> аеродинаміка) можна викликати на кожному етапі RK4. Коли з'явиться перша
> модель зі станом, для цього треба буде додати в `VehicleModel` хук
> `on_substep()`.

## Обмеження поточних моделей

- Літак: немає звалювання (аеродинаміка лінійна за α), тяга не залежить від
  швидкості, немає закрилків.
- Вертоліт: немає динаміки індуктивного потоку, ефекту підсилення тяги при
  поступальному русі та впливу землі. Компенсація реактивного моменту
  хвостовим гвинтом ідеальна (змішування загального кроку й педалей).
- Земля: одна пружинно-демпферна точка під ЦМ. Цього вистачає, щоб стояти
  на ЗПС або майданчику, але це не модель шасі.
- Параметри дублюються в C++ (`*Params`) і MATLAB (`matlab/params`), тому
  синхронізувати їх зараз доводиться вручну.
